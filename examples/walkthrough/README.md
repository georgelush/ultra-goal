# Walkthrough example

> **ILLUSTRATIVE SAMPLE — this is not a real run.**
> Every file in this directory is fabricated for documentation. The project
> (`taskcli`), the commands, the outputs, and the "user" messages shown here
> were written by hand to demonstrate the file formats. The skill itself
> forbids fabricated evidence in a real `.ultra-goal/` — which is exactly why
> this sample must say so up front.

This directory shows what a project's `.ultra-goal/` looks like at the end of
a small tier-M goal on a fictional CLI tool: adding a `--json` output flag.

Read the files in this order to follow the protocol:

1. [`goal.md`](goal.md) — objective, discovery answers, acceptance criteria
2. [`project-audit.md`](project-audit.md) — code reality vs documentation claims
3. [`debate/claude.md`](debate/claude.md), [`debate/codex.md`](debate/codex.md) — per-provider analyses
4. [`debate/synthesis.md`](debate/synthesis.md) — shared conclusions, approach, acceptance checks
5. [`state.md`](state.md) — phase, tier, and the recorded authorization (question + answer verbatim)
6. [`plan.md`](plan.md) — checked steps, exactly one **NEXT** marker
7. [`worklog.md`](worklog.md) — append-only entries, each with evidence

In a real project this directory would be `<project-root>/.ultra-goal/`.
